Stackup

Stackup brings up a single-node Kubernetes cluster on a laptop with one command. kind runs the cluster inside Docker, and ArgoCD keeps it in step with this repository. A small demo service ships through an Argo Rollouts canary: each new version starts on a share of the pods while Prometheus checks the HTTP success rate of those new pods, and the rollout either continues to 100% or rolls back on its own.

Run it

git clone https://github.com/ykstorm/stackup
cd stackup
make up        # or ./setup.sh

make up checks the prerequisites, creates the cluster, installs Calico and ArgoCD, and loads the demo image onto the node. ArgoCD then installs the rest from git in three sync waves, and the script waits until every Application is healthy.

You need

  • Docker with at least 6 GB of memory
  • kind, kubectl, and helm 3.15 or newer
  • the kubectl-argo-rollouts plugin
  • git, bash, openssl and make (on Windows, WSL, or Git Bash with ./setup.sh)
  • ports 80 and 443 free on the host
  • make preflight checks all of this

How a change ships

The demo canary with the default values in helm/demo:

  1. A git push changes helm/demo, for example image.tag: v2.
  2. ArgoCD polls git every two to three minutes, syncs the change and updates the Rollout.
  3. The Rollout moves to a 25% weight, one new pod next to two old ones, and pauses 30 seconds.
  4. An AnalysisRun asks Prometheus for the success rate of the canary pods alone, three times, 30 seconds apart. A measurement passes at 0.95 or above.
  5. While the success rate stays at or above 0.95, the rollout continues to 50, 75 and 100 percent with 30-second pauses.
  6. One failed measurement is tolerated. A second aborts the update, and the old pods keep serving.

The AnalysisRun computes the share of requests to the new pods that returned a 2xx status, where <hash> is the new ReplicaSet's pod-template-hash:

sum(rate(http_requests_total{
  service="demo-canary",
  rollouts_pod_template_hash="<hash>",
  code=~"2.."
}[2m]))
/
sum(rate(http_requests_total{
  service="demo-canary",
  rollouts_pod_template_hash="<hash>"
}[2m]))

What you can open

ArgoCD

argocd.localtest.me
The root Application and its five children, with the sync and health of each. Log in as admin; the password is in the argocd-initial-admin-secret Secret.

Grafana

grafana.localtest.me/d/stackup-canary
The canary dashboard: the gate's success rate per ReplicaSet against the 0.95 line, requests by status code, 5xx responses by pod, and ready pods per ReplicaSet. Log in as admin; the password, generated by make up, is in the grafana-admin Secret.

The rollout

make rollout-status
The Rollout's steps, ReplicaSets and AnalysisRuns, updating in the terminal. make rollout-ui serves the same view as a web page on localhost:3100/rollouts.

localtest.me resolves to 127.0.0.1. The certificates are self-signed, so the browser warns once per host.
