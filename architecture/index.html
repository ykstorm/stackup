Architecture

The node, the GitOps tree, the metrics path, and the security settings, as make up builds them.

The cluster

kind/cluster.yaml defines one node: a control-plane node that also runs every workload. The node is a Docker container running containerd and the kubelet, so pods are containers inside that container. The cluster sets disableDefaultCNI: true and installs Calico, which enforces both the ingress and the egress half of a NetworkPolicy. The node publishes ports 80 and 443 on the host's loopback address, 127.0.0.1, where ingress-nginx binds them, so the UIs answer only on the laptop itself. The stack needs about 6 GB of memory for Docker.

The GitOps tree

make up installs only kind, Calico, the app namespace and ArgoCD, loads the demo image onto the node, and applies one root ArgoCD Application. The root renders argocd/apps/, a small Helm chart that defines five child applications, and ArgoCD installs them in three sync waves:

  • wave 0, cert-manager: certificates for each Ingress
  • wave 0, ingress-nginx: the ingress controller
  • wave 1, kube-prometheus-stack: Prometheus and Grafana
  • wave 1, argo-rollouts: the canary controller
  • wave 2, demo: the canary subject, from the chart in helm/demo

Each wave waits for the previous one to be Healthy, so the demo finds the Rollout and ServiceMonitor CRDs it needs. Each child syncs automatically with prune and self-heal turned on, and applies server-side, because several of the charts ship CRDs too large for a client-side apply. State lives in git rather than in kubectl apply commands.

Metrics

The demo app counts every response in http_requests_total, labelled by service, method, path and status code. kube-prometheus-stack scrapes it through the chart's two ServiceMonitors, one for every pod and one for the canary pods alone, which the canary gate reads:

Grafana reads from that Prometheus. There is no alerting and no log or trace pipeline: the stack collects metrics only.

Moving off kind

On a managed cluster the main changes are a multi-node control plane, a LoadBalancer Service for ingress-nginx instead of hostPort, an ACME issuer instead of the self-signed one, persistent volumes for Prometheus and Grafana, a secret store whose keys outlive the cluster, and a traffic router so canary weights are exact shares of traffic rather than pod counts.
